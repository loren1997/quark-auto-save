# 维护版验证记录

本机：Windows，Python 3.11；全程后台运行。

## 第三版补丁 V3.12：Telegram 扫码与频道自动订阅

- 扫码只在用户点击后启动有界后台连接，最多等待 180 秒；预先监听登录确认、更新过期二维码、处理 DC 迁移与两步验证。页面轮询只读本地状态，离开配置页或页面不可见时停止轮询；二维码由本地库生成，不向第三方图码服务发送登录令牌。
- 扫码接口沿用已认证、同源 JSON 请求限制；随机登录标识隔离不同页面/轮次，普通状态不返回二维码或标识。响应禁止缓存；状态回写保留配置版本检查，不覆盖后台新增任务。
- 账号新增独立自动发现来源，轮换公开关键词和相似频道推荐；候选仍需验证实际夸克影视链接。既有目录和文件夹来源继续自动维护，失败保留旧名单。
- 实际订阅频道需要用户开启并保存独立开关；仅对验证有效的公开广播频道尝试，每轮最多 1 个、滚动 24 小时最多新增 6 个。加入记录按授权会话隔离，限流、审核和付费入口分别退避，加入失败不阻止公开资源搜索，关闭后不自动退出已有频道。
- Telegram 登录、消息、发现和加入均使用假客户端与隔离目录测试，没有读取或操作用户真实账号，也没有使用真实 NAS 转存下载。真实扫码成功及账号发现覆盖范围仍需用户部署后确认。

本机完整回归 630 项：627 项通过，3 项平台条件跳过（真实 Aria2、符号链接与 POSIX 权限留给 Linux CI）。扫码和原有功能两套无界面页面测试通过，无 JavaScript 错误；二维码轮换、旧 nonce、两步验证、离页停轮询、配置并发保护均覆盖。真实 SQLite 双实例检查了加入配额预留与换账号迟到操作；独立复验确认旧验证码不会中断扫码连接。

## 第三版补丁 V3.11：Telegram 频道文件夹、周历显示与按星期换源

- 可选 Telegram 账号使用官方 MTProto 文件夹读取和指定公开频道历史搜索，不加入频道、不发送消息、不调用收费全网搜索。目录和文件夹分别记录成功名单，失败保留旧名单；来源删除只移除该来源的成员。
- 新频道需要真实夸克媒体消息验证；候选限量检查、已验证频道轮换查询。不可访问频道单独停用与复查，不清空用户配置，不把单频道失败扩大到全部 Telegram。
- 登录接口只接受同源已认证 JSON 请求；凭据和会话独立存储，状态/普通配置/运行日志不含凭据。SDK 子日志隔离、跨进程会话锁、总超时和 FloodWait 冷却均有离线回归。账号状态回写沿用配置版本校验，避免覆盖并发新增任务。
- 文件夹公开预览实测能显示标题和频道数量，但不能匿名枚举完整名单；完整解析和真实账号检索尚未实测，需要部署后由用户完成一次登录。

- 周历页面使用后台快照接口，先返回当前周可用数据，再逐来源更新；中文别名与身份补充不阻塞首批作品显示。订阅校验使用完整缓存或独立目标来源，不把尚未加载的作品当成不存在。
- TVmaze 电视/网络排期按实际日期分别保留成功快照，失败时只沿用同周对应来源的数据，标记缓存状态；不将上周内容改写成当前周。真实错误仍保留在可展开的来源提示内，缺少中文名作为普通说明。
- 页面可见且周历更新中时才继续取快照，复用现有定时器；离开热门追更后停止请求周历。刷新和后台失败不会清空已有卡片或订阅错误。
- 失效换源、补集、普通转存和待查找订阅复用运行星期/截止日期判断。待查找队列先筛选本日到期任务再使用每轮 3 个名额，搜索前及提交结果时复验最新周期。非运行日不搜索、不转存、不提交下载，保留原链接和失效状态。
- 手动点击单个任务的立即运行语义保留；定时执行在任务允许的星期、系统定时规则触发时处理，不新增午夜或独立星期计划。

本机完整回归 581 项：578 项通过，3 项平台条件跳过（真实 Aria2、Linux 符号链接与会话文件 POSIX 权限在 Linux CI 检查）。Telegram 相关测试覆盖登录/两步验证、会话脱敏、并发配置保护、文件夹合并、满池新来源准入、暂时停用恢复与超时保留候选；普通页面及 Telegram 页面无界面测试均通过，无 JavaScript 错误。周历 SDK 共 55 项，覆盖冷启动快照、防重复刷新、慢别名、同周分日分来源缓存、跨周隔离，以及刷新异常和缓存缺席时的单部订阅。新增运行周期用例模拟非运行日与周五：前者不触发资源查找、转存或插件，后者完成旧分享复验、换源、转存及 Aria2 插件调用；全部使用隔离夹具。

无界面 UI 检查通过：首个快照即可显示卡片、后台替换说明、明确强刷参数、折叠/展开来源提示、离开页面停止周历轮询、503 时保留卡片与订阅错误、仅勾周二任务的单任务立即运行及批量周期保留。浏览器无 JavaScript 错误，没有操作桌面或用户剪贴板。

一次匿名实网检查只读取公开元数据：首个快照未等待外部请求完成，约 0.5 秒获取首批国漫数据，后台约 15.8 秒结束；当次 Bangumi 请求超时，国漫和电视剧仍正常返回。首个响应落在本机计时器的同一刻度内，不能据此报告零延迟或亚毫秒性能。此结果说明某来源失败不会阻塞其他来源，不能代表 NAS 网络必然具有同样耗时，也不表示外部接口超时已被消除。页面在可见且更新中时约每 2 秒读取新快照。

镜像构建和发行结果见 [V3.11 发布页](https://github.com/loren1997/quark-auto-save/releases/tag/maintenance-v3.11)。周历仍为进程内缓存，重启后首次获取依赖外网；未连接用户 NAS 或使用用户账号进行实际转存下载。

## 第三版补丁 V3.10：新增独立索引、频道发现与故障复查

- 新增 PansoVIP 公开站内搜索，不依赖 PanSou 聚合或 Google；只从适配的搜索/详情结构提取候选，后续仍读取夸克真实目录和视频验证同作品、年季及集号。网页来源开关、时间预算、低并发和失败冷却继续生效；这不是任意网站自动适配器。
- 电视剧周历上限由每周 10 部提高为 50 部，继续使用 TVmaze 已有中国电视/网络真实排期，不新增国家请求，也不填造更新日期。用此前保存的 2026-11-02 至 11-08 中国网络排期快照回放，同一份数据由显示 10 部变为 22 部；新上限不等于来源每周一定收录 50 部。回放不证明本周实时条目数量。
- 扩展展示量后，每次周历实际刷新最多补查 10 个尚未缓存的电视剧官方别名；缓存继续复用，未轮到的先用 TVmaze 原名，下一次刷新继续。单部订阅按需读取该部官方别名，使用既有 10 秒预算、保留季号，失败不永久缓存；年度季号仍不被转换成几千季。
- 仅从固定 PanSou 上游公开频道目录每日发现候选，按固定格式读取 Telegram 频道名；不执行目录内容或安装陌生网站代码。每轮 5 分钟巡检最多验证 3 个频道，最多 6 个启用，查询优先保留自定义名单并遵守每类 6 个频道上限。可用判据包括公开消息中存在影视夸克链接，不把首页 HTTP 200 当成影视资源可用。
- 独立后台巡检首次延迟约 25 秒，每 5 分钟最多复查 2 个冷却已到期的故障来源。只有真实查询/列表响应结构通过才清除故障；仍失败则续冷却，已停用来源不主动探测。它不即时感知恢复，不要求用户处理验证码，也不保证免费稳定突破外站防护。
- 新增默认开启的 `source.monitor.enable` 和 `source.channelsearch.auto_discover`。重载转存定时不会丢失或推迟既有巡检任务；后台巡检不创建转存运行历史。需登录的 `/source_status` 仅返回状态白名单字段，手动刷新界面展示冷却、等待复查和自动频道状态，不返回配置中的 Cookie、Token 或认证地址。
- 本轮匿名只读实测为《乱世千金倪亚·利斯顿转生为娇弱千金的弑神武人华丽无双录》发现新分享 `142c8fed3ff4`，实际视频识别为 `01、02、03、04、06`，**仍缺第 5 集**。找到新分享不等于已补齐；此处没有宣称向用户网盘转存或向 NAS 下载成功。

## 第三版补丁 V3.8.2：公共源故障分类与过期默认频道

- 用户 NAS 诊断确认本地 PanSou、Bangumi、Telegram、TVmaze 的 IPv4 HTTP 可达，部分 IPv6 无路由；HTTP 200 及首页 302 本身不能证明搜索可用。
- 本机匿名 HTTPS 请求公共 PanSou，交替出现健康 200、搜索超时和 HTML 400。400 固定正文提示明文 HTTP 被发送至 HTTPS 端口，指向公共服务反向代理/上游协议问题；不能据此认定 NAS 返回的 400 一定相同。SDK 仅识别这一明确标记，输出固定原因并冷却 5 分钟；其他 400 保留原分类，不猜测是验证码，不输出响应正文。
- 默认 Telegram `Q_dongman` 预览只剩两条消息且无夸克链接，已不再是有效动漫来源。移除应用、模板与 Compose 中的默认引用，仅迁移精确旧工厂名单，自定义名单保持。现有 `guoman4K`、`Quark_Movies`、`leoziyuan` 仍有近期夸克资源；这不证明含用户目标作品。
- 腾讯频道实测 HTTP 200 返回浏览器挑战页，原查询失败判断准确。网络探针增加明确挑战标记和上游协议错误识别，不输出页面正文、Cookie 或代理凭据，不绕过访问验证。
- 本地 PanSou 默认从 5 个插件增至 7 个，加入官方已注册、无需账号的 `quark4k` 与 `quarkres`。各一次匿名公开 API 查询正常返回 JSON，但目标关键词均无结果；接口可用不等于目标作品存在。未加入官方已取消导入的 `qupanshe`，未盲目全开插件。
- 本机回归 436 项，434 通过、2 项平台相关检查交 Linux CI；无头 Chromium 桌面/手机通过。未连接用户 NAS、网盘或下载器；未确认目标作品或缺集自动查找成功。Linux 回归与双架构镜像结果见 V3.8.2 发布页。

## 第三版补丁 V3.8.1：减少重复请求、来源冷却与网络诊断

- 单部订阅按作品 ID 读取日历；Bangumi 作品不再触发整周 TVmaze/Bilibili 请求，TVmaze 只查询目标作品别名。普通热门页继续显示完整周历，局部结果不污染整周缓存。
- Bangumi 别名读取遇到暂态连接或超时时重试一次，作品与同名原作共享 10 秒预算；不重试验证码、403/429 或证书错误。本机匿名读取 `bangumi:624085`，2 次 HTTP 请求、1.19 秒得到 5 个可信名称；不代表用户 NAS 的网络已修复。
- 来源健康状态保存到配置旁的 SQLite，只记录域名、固定原因与冷却截止时间。默认超时 60 秒、429 为 5 分钟、403 为 15 分钟、验证码 30 分钟；支持 `Retry-After`，最多 7 天。重启、其他订阅和手动刷新共享冷却；到期自动尝试，落地页失败不误伤搜索引擎。坏记录和数据库故障保留固定警告并继续查询，不输出凭据。
