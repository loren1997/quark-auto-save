# NAS 安装与使用

本版在原项目基础上维护，保留上游许可证和插件。默认工作方式是：NAS 上运行订阅服务，定时将夸克分享转存到自己的夸克网盘。需要 NAS 本地文件时，可启用已有 Aria2 插件。

V3.10 新增 PansoVIP 公开站内搜索，电视剧周历上限提高到每周 50 部；默认启用公开频道自动发现与后台渠道巡检。遇到验证码会暂时跳过该来源，使用其他来源并在冷却到期后复查，无需人工完成验证。它不会自动适配任意网站，也不能保证外站解除防护或所有缺集都有可用分享。

V3.9 为资源正文读取预留时间，避免被慢搜索源挤掉；简繁片名和字幕组标签不会再直接导致同作品视频被拒绝。遇到网站验证码会跳过该来源，继续其他渠道及原定时重试，无需人工完成验证码。仅对首季 Bangumi 动画，在同一资源主帖、分享目录、全部视频完整片名和集号一致、无明确年份或季度冲突时接受缺少年份的分享，并记录“年份未确认”。这仍有同名翻拍歧义，不等于从文件中验证了年份。

V3.8 可以连续点击多部作品加入订阅队列，依次在后台执行，同一作品重复点击会去重。未执行的队列随配置保存在 NAS，服务重启后继续；正在执行的任务若中断，会在日志标记。首次查询未找到可验证资源的作品会进入“运行日志 → 等待自动查找”，按现有定时规则重试；每轮优先检查最久未尝试的 3 部，其余留到后续轮次。找到后自动转存并按原下载设置提交 Aria2，也可以取消继续查找。

“系统配置 → 资源搜索 → 公开频道索引”可以分别填写 Telegram 频道名与腾讯频道 ID，逗号或换行分隔，每类最多 6 个。默认 Telegram 为 `guoman4K,kuakedongman`，腾讯为 `pd26778899`。Telegram 查询公开消息预览；腾讯只读取可访问的当前公开帖子列表，并非腾讯频道全站或全部历史搜索。各频道只读一页，与网页来源共享有界时间和并发，不会登录、执行脚本或绕过验证。网络防护可能使部分渠道不可用，日志会明确显示。

## 1. 用 Docker Compose 安装

### 与原作者版本并行安装（推荐）

使用 [维护版 V3.11 发布包](https://github.com/loren1997/quark-auto-save/releases/tag/maintenance-v3.11) 中的 `quark-auto-save-nas-docker-v3.11.zip`。将其中三个文件放到独立目录，例如 `/root/quark-save-gpt`；复制 `.env.example` 为 `.env` 并设置管理密码，然后运行：


```sh
cd /root/quark-save-gpt
mkdir -p config
docker compose -p qas-maintained config --quiet
docker compose -p qas-maintained pull
docker compose -p qas-maintained up -d
```

发布包默认端口 **5006**，项目名 `qas-maintained`，没有固定容器名；与原版使用不同目录和数据卷。已有维护版的 `.env` 和 `config/` 必须保留，不要重新复制模板。更新方法见第 6 节。

### 从源码构建

支持安装了 Docker/Container Manager 的 Intel/AMD x86-64 和 ARM64 NAS。以下使用源码构建本维护版，不依赖原作者发布镜像，也不需要 Docker Hub 发布凭据。

仓库根目录的源码 Compose 沿用端口 **5005** 和容器名 `quark-auto-save`；已安装原作者版本时，请使用上面的并行发布包，避免端口和容器名冲突。

1. 将你的维护仓库下载或克隆到 NAS，例如群晖 `/volume1/docker/quark-auto-save`、飞牛 `/vol1/1000/docker/quark-auto-save`。实际存储路径以你的 NAS 为准。
2. 将 `.env.example` 复制为 `.env`，把 `WEBUI_PASSWORD` 改成自己的管理密码。端口被占用时修改 `QAS_PORT`。
3. 在项目目录执行：

   ```sh
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=100 quark-auto-save
   ```

4. 浏览器访问 `http://NAS的局域网IP:5005`，使用 `.env` 中的账号密码登录。

Compose 会同时运行 `quark-auto-save` 和纯 API 版 PanSou。PanSou 只在容器网络中开放，服务地址是 `http://pansou:8888`，不占用 NAS 额外端口。首次新建配置时自动填入该地址。已有配置升级后，在“系统配置 → 资源搜索 → PanSou”中手动改为此地址并保存。

新版 Compose 显式启用 PanSou 的 `labi,zhizhen,shandian,duoduo,muou,quark4k,quarkres` 插件及 5 个公开频道；应用的 `PANSOU_FALLBACK_SERVERS` 同时补充公共 PanSou 聚合源。用户填写的聚合地址优先，补充源在后，总计最多 3 个 PanSou 服务器、客户端并发 2。若不使用该公共源，可删除 Compose 中的 `PANSOU_FALLBACK_SERVERS` 环境变量并重建容器；禁用 PanSou 时环境补充源也不会查询。各渠道可用性取决于 NAS 网络及上游服务。

配置持久化在项目下 `config/`。必须挂载整个目录，目录需可写；请勿只把单个 JSON 文件 bind mount 到容器，本版用原子替换和旁边的 `.lock` 文件保护并发写入。

### 使用 NAS 图形管理器

- 群晖 DSM：Container Manager → 项目 → 新增，选择完整项目文件夹及 `compose.yaml`，准备好同目录 `.env` 后构建并启动。
- 飞牛 fnOS：Docker → Compose 项目，从完整项目目录创建；文件名和环境变量相同。
- 威联通：Container Station 创建 Compose 应用；若界面不支持 `build: .` 的完整构建上下文，可通过 SSH 在项目目录执行上述命令。

旧版只有 `docker-compose` 命令的系统可将命令中的 `docker compose` 替换为 `docker-compose`。使用前确认 NAS 已启用容器功能。

## 2. 第一次配置

1. 在自己的浏览器登录夸克网盘，按原项目方式取得 Cookie，粘贴到系统配置的第一个 Cookie 输入框并保存。不要将 Cookie、Aria2 密钥或真实 `config/` 上传 GitHub。
2. 确认 PanSou 启用，服务器是 `http://pansou:8888`。首次搜索可能需要等待索引源返回。
3. 设置“热门订阅的夸克网盘保存目录”，默认 `/cartoon`。文件直接放入此目录，不再追加剧名或来源子目录。
4. 默认每天 08:00、18:00、20:00 检查更新；可用 Crontab 调整。
5. 先在任务列表添加一个自己有权保存的分享，运行并检查日志与实际网盘目录。

新安装的任务列表为空，不会自动转存上游示例资源。原有 `config/quark_config.json` 的订阅不会被模板替换。

只转存白名单视频和字幕；图片、文本、压缩包和可执行文件均跳过。分享中的目录会逐层检查，允许的文件平铺到任务保存目录，不整文件夹转存。热门任务默认按 `片名 S01E01.原后缀` 命名，明确第三季使用 `S03`；MKV、MP4、ASS、SRT 等保留原后缀，不进行转码。无法可靠识别集号时保留原文件名，已有自定义命名规则保留。

## 3. 搜索与自动换源

V3.10 新增 **PansoVIP**，作为与 Meijusou 并列的公开站内搜索来源，随“网页搜索”开关控制。程序读取搜索结果及资源详情页，提取夸克分享后继续验证真实视频；无需为该适配器填写账号或 API 密钥。它与 PanSou 聚合服务不同，不需要将 PansoVIP 网址填写到 PanSou 服务器地址中。站点故障、限流或要求验证时，其他来源继续查询。

### 自动发现频道与后台巡检

“系统配置 → 资源搜索”新增两个默认开启的选项，保存后生效：

| 设置 | 配置项 | 行为 |
| --- | --- | --- |
| 自动发现并验证新的公开频道 | `source.channelsearch.auto_discover` | 从固定上游目录发现 Telegram 频道，验证后按查询上限补充；关闭后仍保留自定义频道。 |
| 每 5 分钟后台巡检 | `source.monitor.enable` | 在后台检查到期故障来源及候选频道；关闭后停止后台巡检，普通订阅仍按原定时规则执行。 |

自动发现同时要求“公开频道索引”和“渠道巡检”开启。程序每天至多读取一次固定的 [PanSou 上游频道目录](https://github.com/fish2018/pansou/issues/4)，只解析约定格式的公开 Telegram 频道名，不安装目录或陌生网站中的代码，也不据此自动接入新类型网站。每轮 5 分钟巡检最多验证 3 个频道，并发不超过 2；发现影视夸克链接的频道才可进入可用列表，最多启用 6 个，其余为待验或备用。查询时优先使用你的自定义频道，再用已验证频道补足最多 6 个 Telegram 频道，不覆盖或删除配置名单；已填满 6 个自定义频道时不会额外加入自动频道。

后台巡检在服务启动约 25 秒后首次执行，之后每 5 分钟检查一次。每轮最多复查 2 个冷却已到期的故障搜索来源，使用真实搜索/公开列表请求检查响应结构；成功才清除故障，失败继续冷却。停用的来源不主动探测，网站的 `Retry-After` 仍受尊重。冷却到期意味着允许复查，并不代表来源已经恢复；较多故障会分轮检查，不是即时恢复通知。频道验证成功、搜索结构正常，也不等于找到了目标作品或缺失集。

点击“查看渠道状态”或“刷新渠道状态”，可查看故障域名、冷却/待复查状态、自动频道的可用/备用/待验状态及检查时间；该列表只在点击时刷新，不轮询整页。只有登录后才能读取状态，接口不返回 Cookie 或 Token。后台巡检不加入转存队列，也不会每 5 分钟新增一条任务运行历史。自动频道与巡检状态保存在配置目录的搜索状态数据库，备份整个 `config/` 即可。

### 既有搜索行为

V3.8.2 另识别 PanSou 明确的 HTTP/HTTPS 上游协议错误，冷却 5 分钟后再试；普通 HTTP 400 不会被误判为验证码。旧默认 Telegram 频道 `Q_dongman` 已不再发布动漫资源，更新只迁移精确旧工厂名单；用户自定义列表保持。

V3.8.2 的 Compose 为本地 PanSou 增加 `quark4k`、`quarkres`，共 7 个无需额外账号的索引插件，降低对公共备用服务的依赖。它们的匿名公开接口已检查，但不能保证任一作品有结果；如果在系统配置中自行限定了 PanSou 插件名单，该筛选仍会保留。

V3.8.1 在不同订阅和进程间共享来源冷却：超时默认 60 秒、HTTP 429 默认 5 分钟、HTTP 403 默认 15 分钟、验证码默认 30 分钟；网站提供 `Retry-After` 时按其要求等待，最多 7 天。日志显示原因和剩余秒数，其他健康来源继续查询，冷却到期后重新尝试。手动刷新不会强行绕过冷却。状态保存在 `config/quark_config.search-health.sqlite3`，不含 Cookie 或搜索词；V3.10 还在其中记录自动频道名称、验证结果与复查时间，无需手工编辑。

在任务名称中输入资源名，或点击名称旁的搜索按钮。PanSou 兼容新版原生接口和公共代理接口；支持提取码。可填写多个 PanSou 聚合地址，每行一个；主源、聚合源与启用的 CloudSaver 会一起查询、去重，并标注来源。单个源失败不影响其他源的结果，全部失败时明确报错。频道和插件筛选留空时使用 PanSou 服务已启用的全部渠道，也可填写逗号分隔的名称进行筛选。

V3.6 将找到的资源线索独立保存到 `config/quark_config.resources.json`，仅保存标题、别名和分享链接。删除订阅不会清除这些线索；重新一键订阅、自动换源和补集时，会尝试匹配的历史链接，并实时验证分享及实际视频，失效或不匹配时继续搜索其他来源。历史记录不代表链接永久有效，也不会使已删除的任务自行恢复。

第 6 节的更新命令会自动读取安装目录下的当前配置与 `backup-v*/config/quark_config.json`，按修改时间最多检查 10 份配置，导入其中的资源线索。它只写入独立线索文件，不恢复订阅、Cookie 或其他旧设置；以后备份时保留整个 `config/` 即可。

在一次自动查找中会记住失败的索引来源，后续译名查询不再重复等待该来源；其他健康来源继续查询。后续任务在来源冷却到期后重新尝试，不会修改或永久禁用搜索配置。日志保留首次超时等失败原因。

同一次自动查找也会记住失败的网页搜索引擎，查询其他别名时只继续使用健康引擎；后续任务在来源冷却到期后重新尝试。资源落地页的 HTTP 403 等错误只冷却该页面实际域名，不会因此禁用已经成功返回搜索结果的引擎。

搜索会从索引返回的结构化结果和公开帖子正文中提取夸克链接、就近关联提取码。“网页搜索”默认启用，查询 PansoVIP、Meijusou 公开站内搜索，并通过搜狗、Google、DuckDuckGo 和 Bing 查询公开网页，再读取有限数量的结果页面提取夸克链接。任务列表搜索会合并这些结果；自动订阅与失效换源在历史线索和索引未找到可验证候选时再补搜网页。页面不执行脚本、不登录，也不绕过验证码；搜索引擎返回验证码或网络失败会明确报错。

搜索结果摘要中的完整夸克链接同样进入候选验证；落地页 HTTP 403 等错误不会丢弃已经取得的候选。部分搜索源失败时继续使用其他来源的结果。错误导致的空结果不缓存为“没有资源”，再次操作会重新查询。

网页搜索使用独立请求，不使用账号 Cookie、`.netrc` 或操作系统保存的代理配置；NAS 必须能访问对应搜索引擎和网页。可在容器环境中显式设置 `HTTP_PROXY` / `HTTPS_PROXY` 使用自己信任的代理，代理负责最终域名解析和转发。网络受限时也可在系统配置关闭“网页搜索”，继续使用自托管 PanSou/CloudSaver。网页来源及真实标题会保留，自动订阅仍检查夸克分享中的实际文件。

使用仓库或发布包的 Compose 时，可在 `.env` 增加 `QAS_PROXY=http://你的代理局域网地址:端口`，然后 `docker compose -p qas-maintained up -d` 重建容器；V3.8.1 会让应用与 PanSou 同时使用该代理。默认不启用代理；不要把 NAS 以外的代理写成 `127.0.0.1`，该地址在容器内指向容器自身。代理不能保证解除网站验证码或封禁。

“分享失效时自动搜索并替换”默认启用。每次正常任务运行时，会重新检查原分享和旧版标记失效的分享；明确取消、过期、不存在，或完整扫描确认分享不含视频时，会尝试查找新来源。只有字幕的分享也不作为视频资源。登录、提取码、网络和限流错误，以及未完成的分页或目录扫描，都不会被误判为无视频，会保留原订阅，下次重试。

候选需满足标题、季数和已知年份约束，并确认实际分享包含视频；纯字幕、文档或广告候选会跳过并继续查找。普通订阅和换源的索引最多检查 5 个候选，网页补搜最多检查 3 个新候选；每层目录最多验证 3 页，未完整读取时不贸然确认。无法可靠匹配时保留原订阅并输出日志。换源沿用任务当前的目录、筛选、命名和周期；旧分享的 `startfid` 无法迁移，会清除。最近 10 次替换记录仅保存分享 ID，不包含验证 token。

夸克接口的总数可能与实际可见条目数不一致。V3.4 会以成功读取的空终页确认列表结束，不再仅因计数差异拒绝有效分享；分页达到上限、超时或读取失败仍按未完成处理，不据此认定无视频。

热门订阅会使用目录来源的别名，包括 Bangumi 中原名相同且明确关联为原作书籍的中文译名。最多保留 8 个别名，普通订阅和换源先查询不带年份的不同名称，再补充季号写法与基础片名；索引阶段最多 12 个关键词并设有时间预算，连续两次所有源失败会提前进入网页补搜。普通网页补搜最多 2 个名称，补集另有包含缺号的查询。查询时去掉年份或季数不代表取消验证约束。

同一实际目录的片名与视频的 `S03E09` 等季号可联合验证。多季合集中有唯一且明确匹配的目标季目录时，订阅会指向该子目录；不会把其他季一起加入。目录中混入冲突季数、旧电影或仅有不完整片名时仍拒绝自动订阅。视频名中的月份标签、已知版本标签和独立的零补齐集数会被识别；不会猜测被替换的片名字词。具名视频与其父目录可分别提供可信别名和年份，缺少年份或存在冲突时仍拒绝。可在独立“运行日志”页了解已尝试关键词及来源故障；部分源不可用不会被表述成全网没有资源。

查询数量、页面大小和并发均有限制。时间预算用于停止后续查询，V3.5 不再因已耗时超过预算而丢弃本轮已经返回的候选。操作系统 DNS 解析和远端缓慢发送响应头仍可能延长实际等待时间。

自动查询复用搜索服务缓存，避免每次订阅强制重新抓取全部频道；每个候选分享仍实时验证。需要强制刷新索引时，可使用任务列表的手动搜索按钮。

V3.11 的定时换源、补集和待查找重试统一遵守任务的运行星期及截止日期。例如任务只勾选周五，即使链接已标记失效，周一至周四也不会查找替代资源；周五系统定时运行时再复验旧分享、寻找有效链接，并继续转存及调用下载插件。非运行日任务保留原设置，也不占用每轮待查找重试的 3 个名额。手动点击单个任务“▶运行”仍立即执行；批量运行按保存的任务周期判断。此功能不另建周五零点计划，系统定时规则需要覆盖该运行日。

开启“删除子目录后重存”的任务不会自动换源，以免新来源触发已有删除规则。单任务可在 JSON 配置中设置 `auto_repair: false` 禁用换源。

热门订阅运行时还会检查明确集号之间的缺口，例如 `01、03、04、05、05.mkv` 去重后缺第 2 集；从其他通过同作品、同季、已知年份验证的分享中仅补入缺号，再交给下载插件，保留原订阅继续追更。V3.6 每轮最多使用 3 份不同候选分享，每次按剩余缺号继续查找；120 秒预算用于停止发起下一轮查询，已返回的候选仍会验证和转存。未补齐会打印剩余缺号并在下次运行重试。不会根据文件数量推断集数，也不猜测首集之前或最新集之后是否还缺集。

资源标题只写片名、没有标注总集数或“全集”，也会检查分享目录内的实际视频。只有真实文件中包含缺号且符合当前转存规则才补入；例如缺第 2、4 集时，可分别从两份同作品分享补齐，不重复保存已有集数。备用分享失效不影响原订阅；补集文件改名失败会保留目标文件记录，下次按文件 ID、原名和保存路径核对后重试，成功改名再交下载插件。

补集索引优先使用“片名 02”和可信中文别名等缺号查询，再搜索整季分享，也会尝试“片名 第2集”等写法；V3.7 网页搜索先查基础片名和别名，再查带缺号的关键词，避免漏掉标题没有集数的合集；搜索多个缺号时先围绕最早缺号查询，同一分享内其他已缺集数也可一起补入。各关键词先检查少量新候选，再处理剩余候选，避免首个词的结果占满所有机会；补集索引最多检查 12 个、网页最多检查 8 个新候选。视频判定与正常转存共用扩展名白名单，不因接口分类标错漏掉视频。失败日志会列出实际查询词，以及已验证同作品但不含符合转存规则缺号视频的候选数量，便于区分搜索源故障与分享本身缺集。

自动补集目前限单季、可可靠解析集号的热门任务；使用起始文件、重新编号、删除重存、混合季目录或无法识别文件名时跳过。有界检查作品目录下的字幕组子目录；各组分别核对片名、季数与实际视频，不合并不同组的同集文件。无法找到包含缺号的有效分享时会保留原状并说明原因，不表示资源已完整。关闭“分享失效时自动搜索并替换”也会关闭自动补集。

V3.7 已在新的公开分享中匿名读到《黑暗召唤师在地下恋爱中》的第 2 集：文件位于字幕组子目录，带发布组前缀及 WebRip/编码标签。新版会识别这类发行文件名，保留按“片名 S01E02”更名的规则。仅在补集中，已存在的热门订阅主分享当前仍通过严格校验、备用实际视频完整片名或确认别名吻合且属于首季时，允许备用资源未标年份；明确冲突年份或季数依然拒绝。候选自身年份仍未获证实，同名翻拍存在版本歧义；日志会说明这一匹配依据。初次订阅和失效换源保持原有年份要求，不以发帖日期推断作品年份。

新增来源也可能超时或要求人工验证，日志会分别记录；不会把来源故障当成全网没有资源。找到了链接仍需读取真实视频，不能凭帖子标题认定补齐。本机验证不使用你的 Cookie、不向你的网盘转存，也不向你的 Aria2 提交任务；NAS 的最终补集和下载结果需要更新后运行日志确认。

共享 `/cartoon` 中的旧同名文件，若无法通过文件摘要或待改名身份记录核对归属，会保留原状并提示无法确认归属，以免修改其他作品。这条提示不阻止后续缺集查找，与补集搜索源失败分别处理。

## 4. 热门追更

左侧“热门追更”按周一到周日显示，分国漫、动漫、电视剧，默认打开国漫。一键订阅会立即提交后台任务：搜索并验证资源，再保存订阅和转存，之后按系统定时规则持续追更。关闭页面不会中断正在搜索或转存的任务；重复订阅会复用已存在的任务。

一键搜索失败后，可在报错下方粘贴该作品的夸克分享链接（可包含提取码）。此方式直接验证所填分享，不依赖搜索引擎；仍需通过同作品、同季、已知年份及实际视频检查，成功后沿用原订阅目录、命名和 Aria2 设置。请粘贴夸克分享链接，而非 Google 搜索页或普通资源帖子。

- 国漫整合哔哩哔哩官方国创周历与 TVmaze 中国电视/网络播出排期，无论 Bangumi 是否可用均独立显示；TVmaze 国漫最多收录本周 60 部，实际数量以来源为准。同日同规范标题优先显示 B站官方条目，不合并明确不同季的标题。
- 国漫按来源分组、各自热度排序，B站追番人数不与 TVmaze 的 0–100 热度混算。B站条目显示集数及已发布、待发布或延期状态。
- 动漫使用 Bangumi 当季周播表，按“在看人数”排序，并排除首播日期仍在未来的条目。该表不保证反映临时停播、调档。
- 电视剧使用 TVmaze 中国电视和网络播出日历，V3.10 从每周最多 10 部扩展为热度前 50 部，仍按实际集日期归日；没有真实排期的作品不会为了凑数量而加入，不代表全网完整影视榜。
- Bangumi 不可达时，优先使用本周缓存；无缓存时提示来源错误，国漫栏目继续可用。
- 电视剧与 TVmaze 国漫保留普通季号，避免第四季误订到首季；来源的年份型季号不会被当成几千季。国内年番与来源季号不一致时，可能需要手动选取正确分享。来源未提供当前季年份或重拍版本时，请核对实际目录。
- 周历每次实际刷新最多为 10 部尚无缓存的电视剧补取 TVmaze 官方中文别名；已缓存的全部复用，其余先显示来源原名，后续刷新逐批补齐。订阅单部作品时再按需读取该部官方别名，共用既有 10 秒预算并保留季号；失败不会永久缓存为空。扩展展示量不会一次额外请求 40 部别名。
- TVmaze 官方链接指向同一哔哩哔哩节目时，会核对 B站媒体/季度 ID，在同日同系列的重复条目中优先保留 B站周历，避免将连续更新误显示为额外一季。身份核对失败时保留来源条目，不凭相似片名合并。
- V3.11 先返回可用快照，动漫、国漫和电视剧逐来源显示；中文别名补充在后台进行，不等待全部来源才显示卡片。刷新按钮启动一次后台更新，重复请求共用正在进行的刷新，不叠加外部查询。
- 完整数据缓存一小时，部分错误时缩短为五分钟。同周单日接口失败时沿用该来源该日期的成功快照并标记缓存，其他正常来源继续更新；上周数据不会冒充本周。真实错误可展开“排期来源提示”查看，缺中文名先显示原名。
- 页面可见且更新中时才继续获取快照，离开热门追更后停止周历轮询；订阅校验不会使用尚未完整加载的空快照。
- 新热门订阅每日按定时规则检查；周历展示首播安排，网盘资源上传时间可能更晚，所以不会只在播出当天检查。

## 5. 下载到 NAS 本地磁盘

本项目已有 Aria2 下载插件，安装或使用 NAS 上现有的 Aria2 服务后：

1. 系统配置 → 插件 → aria2，填写 `host_port`（如 `http://NAS局域网IP:6800`）、`secret` 和 `dir`。
2. `dir` 是 **Aria2 进程看到的下载根目录**，默认填写 `/downloads`。热门任务的 `save_path` 为 `cartoon`，所以文件直接下载到 `/downloads/cartoon`，不再追加剧名或来源子目录。NAS 上的实际位置由 Aria2 容器的目录挂载决定。
3. 开启“热门订阅通过 Aria2 下载到 NAS”并保存。仅填写 RPC 连接参数不会启用下载。
4. 保存后，新旧热门订阅都会启用下载；刚启用的旧任务会在下一次运行时补交符合条件的视频。默认不下载字幕，需要时将该任务 `addition.aria2.download_subtitles` 设为 `true`。到“任务列表”运行原任务即可，无需删除文件或重新订阅。
5. 日志出现 `Aria2已提交` 和 `GID` 表示下载器已受理；实际进度、完成情况和磁盘路径在 Aria2 查看。RPC 未连接、任务未开启、请求被拒绝会分别提示。

无法提交的文件及未扫描成功的子目录会保留到下次运行重试，即使没有新转存也会重试；不保存临时下载直链或 Cookie。普通手动任务仍使用自己的 `addition.aria2` 设置：开启 `auto_download`，需扫描旧子目录时开启 `download_subdir`，下载仍平铺到目标目录；要补交历史文件，可将 `download_existing` 设为 `true`，完成扫描后自动关闭。共享目录补交只选择能按当前任务标准命名规则确认归属的文件；不认领其他剧集或纯集号文件。重命名失败的文件保留待办，成功更名后才提交下载。显式再次补交会重新提交目录中的允许文件，适用于此前尚未下载的任务。

这里不内置第二套下载器；Aria2 负责下载队列、磁盘空间和重试。夸克 Cookie、账号权限和下载直链可用性会影响实际下载。系统中“通知测试”按钮包含上游的转存/清理测试；建议验收自己的独立测试目录。

### 静默运行与实时日志

点击运行或一键订阅后，不再自动弹出日志窗口。左侧“运行日志”可查看当前作品、正在查询的来源/关键词，以及验证、补集、转存、更名和提交下载等步骤。页面每 2 秒增量更新，刷新或重新打开后可继续查看；手动和定时任务共用一个执行锁，避免同时重复转存。

运行记录保存在 `config/runs/`，保留最近 20 次，每次最多 1000 行、约 512 KiB 文本。Cookie、密钥及下载直链会脱敏。“运行结束”只表示本轮程序退出，缺集未完成等结果会单独提示；“提交下载任务”不代表 Aria2 已下载完毕。停止或升级容器会中断当前任务，重新启动后日志会标记中断。

## 6. 更新、备份与回退

V3.3 会迁移工厂默认设置：热门任务原 `/追更/片名` 改为 `/cartoon`，空白或旧默认命名改为 `片名 S01E01.原后缀`；全局旧默认 `/Downloads` 改为 `/downloads`。自定义目录和命名规则保留。实际迁移旧目录的任务会清除旧下载待办，已开启下载的任务重新检查新目录。更新只调整配置与后续任务，不移动或删除 NAS 上已有文件。

### 已安装并行发布包（`/root/quark-save-gpt`）

以下从旧维护版更新至 V3.11：先下载并检查新配置、拉取镜像，再停止维护版并备份，最后自动导入旧配置中的资源线索并启动；保留原 `.env`、Cookie、订阅和端口，不影响原作者版本。

```sh
(
set -e
cd /root/quark-save-gpt
curl -fL --retry 2 https://github.com/loren1997/quark-auto-save/releases/download/maintenance-v3.11/compose.yaml -o compose.yaml.next
docker compose -p qas-maintained -f compose.yaml.next config --quiet
docker compose -p qas-maintained -f compose.yaml.next pull
backup="backup-v3.11-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
docker compose -p qas-maintained stop quark-auto-save
cp -a compose.yaml .env config "$backup/"
mv compose.yaml.next compose.yaml
docker compose -p qas-maintained run --rm --no-deps --entrypoint python -v "$PWD:/history:ro" quark-auto-save scripts/recover_resource_history.py --root /history
docker compose -p qas-maintained up -d
docker compose -p qas-maintained ps
)
```

导入步骤以只读方式挂载安装目录，输出读取的配置份数和新增线索数，不需要手动粘贴旧分享链接。若旧任务已删除，当前配置及保留的备份中也没有该链接，就仍需由搜索渠道重新发现；导入不会恢复旧任务。

更新后强制刷新浏览器页面。默认仍访问 `http://NAS局域网IP:5006`；如果 `.env` 改过 `QAS_PORT`，继续使用该端口。需要回退时停止维护版，将这次备份中的 `compose.yaml`、`.env` 和 `config/` 恢复到原位置后重新 `up -d`。

### 从源码构建的安装

更新前备份整个 `config/` 目录。在项目目录：

```sh
docker compose stop quark-auto-save
cp -a config "config-backup-$(date +%Y%m%d-%H%M%S)"
git pull --ff-only
docker compose up -d --build
```

下载 ZIP 安装的用户可覆盖代码文件，再执行构建；保留 `.env` 和 `config/`。不要用上游 Watchtower 更新命令替换本维护版镜像。

回退时停止服务，检出上一个已验证提交或换回之前代码，再恢复对应配置备份、重新构建。备份里可能含 Cookie，妥善保管。

GitHub Actions 会先跑 Python 3.11/3.13 测试，再构建 amd64/arm64 镜像到该仓库的 GHCR。Fork 的 Actions 可能需要你先在 GitHub 的 Actions 页启用；仓库连接器还需要有该 Fork 的访问权限。镜像第一次发布后若为 private，需要在 Packages 中设为 public 或在 NAS 登录 GHCR；本地 `build` 安装不受此影响。只有 Actions 实际通过后才能确认远程镜像已发布。

## 7. 排错与验收

HTTP 200 可能仍是浏览器验证页；新版探针会输出 `browser_verification_required`。`upstream_protocol_error` 表示响应明确提示上游 HTTP/HTTPS 协议错误，需要该服务维护者修复；应用会冷却并切换其他来源。`read_limit` 只是探针达到有界读取上限，并不表示网页不可访问。本地 PanSou 的 `172.*` 容器内网地址正常；只有搜索发现的外部落地页受私网地址限制。

V3.8.1 可在 NAS 安装目录执行只读网络检查：

```sh
docker compose -p qas-maintained exec -T quark-auto-save python scripts/probe_sources.py
```

它检查固定来源的 DNS、IPv4/IPv6 连通性和匿名 HTTP，只显示代理是否启用，不读取账号配置、Cookie 或密钥，也不转存下载。`--direct` 可额外比较不使用代理时的结果。健康接口正常并不能证明 PanSou 实际搜索正常；HTTP 200 也可能是验证页面。出现“地址解析为非公网 IP”时应结合检查结果确认是否为真实私网链接或 DNS/代理的 fake-IP 设置，不要关闭私网保护。单部订阅现在只读取目标作品的日历来源，不再为订阅动漫查询无关电视剧别名。

- 无法搜索：查看页面源错误和 `docker compose logs --tail=100 pansou`；确认地址为 `http://pansou:8888`。公共 `https://so.252035.xyz` 可作备用，但没有稳定性保证。
- 动漫源超时：页面会显示降级。如果你有自己的网络代理，可在 Compose 的服务 `environment` 中配置标准 `HTTPS_PROXY`，同时设置 `NO_PROXY: localhost,127.0.0.1,pansou`；不要关闭 TLS 校验。无需代理也能查看可达来源。
- “未找到匹配的有效资源”：展开“查看搜索详情”区分来源故障与候选验证失败；已有有效分享时，可在热门页报错下粘贴该作品的夸克链接直接验证订阅。日历有片名不保证分享存在或可用。
- 网页搜索会分别显示 Google、DuckDuckGo、Bing 及落地页的 DNS、TLS、代理、验证码、超时等错误；只有真实代理故障才需要检查代理设置。NAS 能正常搜到候选而验证失败时，应核对实际文件名称和目录年份。
- “配置已被更新”：任务自动换源或另一页面写入了新配置。刷新后重新编辑，避免把新订阅或修复结果覆盖掉。
- 订阅已创建但没转存：查看手动运行日志、Cookie 是否有效、目标网盘空间；在任务列表运行该任务重试。
- NAS 没有本地文件：先看网盘是否已转存，再检查 Aria2 的连接、密钥、容器目录映射和该任务 `auto_download` 选项。

建议验收顺序：登录 → 名称搜索 → 自有分享的单任务转存 → 热门周历切换 → 一键订阅 → 日志/网盘验证 → 按需验证 Aria2 本地文件。自动换源与并发保存已经有可重复模拟测试；真实账号操作需在你自己的环境完成。
