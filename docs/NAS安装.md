# NAS 安装与使用

本版在原项目基础上维护，保留上游许可证和插件。默认工作方式是：NAS 上运行订阅服务，定时将夸克分享转存到自己的夸克网盘。需要 NAS 本地文件时，可启用已有 Aria2 插件。

## 1. 用 Docker Compose 安装

### 与原作者版本并行安装（推荐）

使用 [维护版 V3.4 发布包](https://github.com/loren1997/quark-auto-save/releases/tag/maintenance-v3.4) 中的 `quark-auto-save-nas-docker-v3.4.zip`。将其中三个文件放到独立目录，例如 `/root/quark-save-gpt`；复制 `.env.example` 为 `.env` 并设置管理密码，然后运行：

```sh
cd /root/quark-save-gpt
mkdir -p config
docker compose -p qas-maintained config --quiet
docker compose -p qas-maintained pull
docker compose -p qas-maintained up -d
```

发布包默认端口 **5006**，项目名 `qas-maintained`，没有固定容器名；与原版使用不同目录和数据卷。已有维护版的 `.env` 和 `config/` 必须保留，不要重新复制模板。更新方法见第 6 节。

### 从源码构建

支持安装了 Docker/Container Manager 的 Intel/AMD x86-64 和 ARM64 NAS。以下使用源码构建本维护版，不依赖原作者发布镜像，也不需要 Docker Hub 发布凭据。

仓库根目录的源码 Compose 沿用端口 **5005** 和容器名 `quark-auto-save`；已安装原作者版本时，请使用上面的并行发布包，避免端口和容器名冲突。

1. 将你的维护仓库下载或克隆到 NAS，例如群晖 `/volume1/docker/quark-auto-save`、飞牛 `/vol1/1000/docker/quark-auto-save`。实际存储路径以你的 NAS 为准。
2. 将 `.env.example` 复制为 `.env`，把 `WEBUI_PASSWORD` 改成自己的管理密码。端口被占用时修改 `QAS_PORT`。
3. 在项目目录执行：

   ```sh
   docker compose up -d --build
   docker compose ps
   docker compose logs --tail=100 quark-auto-save
   ```

4. 浏览器访问 `http://NAS的局域网IP:5005`，使用 `.env` 中的账号密码登录。

Compose 会同时运行 `quark-auto-save` 和纯 API 版 PanSou。PanSou 只在容器网络中开放，服务地址是 `http://pansou:8888`，不占用 NAS 额外端口。首次新建配置时自动填入该地址。已有配置升级后，在“系统配置 → 资源搜索 → PanSou”中手动改为此地址并保存。

新版 Compose 显式启用 PanSou 的 `labi,zhizhen,shandian,duoduo,muou` 插件及 6 个公开频道；应用的 `PANSOU_FALLBACK_SERVERS` 同时补充公共 PanSou 聚合源。用户填写的聚合地址优先，补充源在后，总计最多 3 个 PanSou 服务器、客户端并发 2。若不使用该公共源，可删除 Compose 中的 `PANSOU_FALLBACK_SERVERS` 环境变量并重建容器；禁用 PanSou 时环境补充源也不会查询。各渠道可用性取决于 NAS 网络及上游服务。

配置持久化在项目下 `config/`。必须挂载整个目录，目录需可写；请勿只把单个 JSON 文件 bind mount 到容器，本版用原子替换和旁边的 `.lock` 文件保护并发写入。

### 使用 NAS 图形管理器

- 群晖 DSM：Container Manager → 项目 → 新增，选择完整项目文件夹及 `compose.yaml`，准备好同目录 `.env` 后构建并启动。
- 飞牛 fnOS：Docker → Compose 项目，从完整项目目录创建；文件名和环境变量相同。
- 威联通：Container Station 创建 Compose 应用；若界面不支持 `build: .` 的完整构建上下文，可通过 SSH 在项目目录执行上述命令。

旧版只有 `docker-compose` 命令的系统可将命令中的 `docker compose` 替换为 `docker-compose`。使用前确认 NAS 已启用容器功能。

## 2. 第一次配置

1. 在自己的浏览器登录夸克网盘，按原项目方式取得 Cookie，粘贴到系统配置的第一个 Cookie 输入框并保存。不要将 Cookie、Aria2 密钥或真实 `config/` 上传 GitHub。
2. 确认 PanSou 启用，服务器是 `http://pansou:8888`。首次搜索可能需要等待索引源返回。
3. 设置“热门订阅的夸克网盘保存目录”，默认 `/cartoon`。文件直接放入此目录，不再追加剧名或来源子目录。
4. 默认每天 08:00、18:00、20:00 检查更新；可用 Crontab 调整。
5. 先在任务列表添加一个自己有权保存的分享，运行并检查日志与实际网盘目录。

新安装的任务列表为空，不会自动转存上游示例资源。原有 `config/quark_config.json` 的订阅不会被模板替换。

只转存白名单视频和字幕；图片、文本、压缩包和可执行文件均跳过。分享中的目录会逐层检查，允许的文件平铺到任务保存目录，不整文件夹转存。热门任务默认按 `片名 S01E01.原后缀` 命名，明确第三季使用 `S03`；MKV、MP4、ASS、SRT 等保留原后缀，不进行转码。无法可靠识别集号时保留原文件名，已有自定义命名规则保留。

## 3. 搜索与自动换源

在任务名称中输入资源名，或点击名称旁的搜索按钮。PanSou 兼容新版原生接口和公共代理接口；支持提取码。可填写多个 PanSou 聚合地址，每行一个；主源、聚合源与启用的 CloudSaver 会一起查询、去重，并标注来源。单个源失败不影响其他源的结果，全部失败时明确报错。频道和插件筛选留空时使用 PanSou 服务已启用的全部渠道，也可填写逗号分隔的名称进行筛选。

搜索会从索引返回的结构化结果和公开帖子正文中提取夸克链接、就近关联提取码。“网页搜索”默认启用，通过 DuckDuckGo 和 Bing 查询公开网页，再读取有限数量的结果页面提取夸克链接。任务列表搜索会合并这些结果；自动订阅与失效换源在索引未找到可验证候选时再补搜网页。页面不执行脚本、不登录，也不绕过验证码；搜索引擎返回验证码或网络失败会明确报错。

搜索结果摘要中的完整夸克链接同样进入候选验证；落地页 HTTP 403 等错误不会丢弃已经取得的候选。部分搜索源失败时继续使用其他来源的结果。错误导致的空结果不缓存为“没有资源”，再次操作会重新查询。

网页搜索使用独立请求，不使用账号 Cookie、`.netrc` 或操作系统保存的代理配置；NAS 必须能访问对应搜索引擎和网页。可在容器环境中显式设置 `HTTP_PROXY` / `HTTPS_PROXY` 使用自己信任的代理，代理负责最终域名解析和转发。网络受限时也可在系统配置关闭“网页搜索”，继续使用自托管 PanSou/CloudSaver。网页来源及真实标题会保留，自动订阅仍检查夸克分享中的实际文件。

使用仓库或发布包的 Compose 时，可在 `.env` 增加 `QAS_PROXY=http://你的代理局域网地址:端口`，然后 `docker compose up -d` 重建应用容器。默认不启用代理；不要把 NAS 以外的代理写成 `127.0.0.1`，该地址在容器内指向容器自身。

“分享失效时自动搜索并替换”默认启用。每次正常任务运行时，会重新检查原分享和旧版标记失效的分享；明确取消、过期、不存在，或完整扫描确认分享不含视频时，会尝试查找新来源。只有字幕的分享也不作为视频资源。登录、提取码、网络和限流错误，以及未完成的分页或目录扫描，都不会被误判为无视频，会保留原订阅，下次重试。

候选需满足标题、季数和已知年份约束，并确认实际分享包含视频；纯字幕、文档或广告候选会跳过并继续查找。索引最多检查 5 个候选，网页补搜最多检查 3 个新候选；每层目录最多验证 3 页，未完整读取时不贸然确认。无法可靠匹配时保留原订阅并输出日志。换源沿用任务当前的目录、筛选、命名和周期；旧分享的 `startfid` 无法迁移，会清除。最近 10 次替换记录仅保存分享 ID，不包含验证 token。

夸克接口的总数可能与实际可见条目数不一致。V3.4 会以成功读取的空终页确认列表结束，不再仅因计数差异拒绝有效分享；分页达到上限、超时或读取失败仍按未完成处理，不据此认定无视频。

热门订阅会使用目录来源的别名，包括 Bangumi 中原名相同且明确关联为原作书籍的中文译名。最多保留 8 个别名，先查询不带年份的不同名称，再补充季号写法与基础片名；索引阶段最多 12 个关键词并设有时间预算，连续两次所有源失败会提前进入网页补搜。网页补搜最多 2 个名称。查询时去掉年份或季数不代表取消验证约束。

同一实际目录的片名与视频的 `S03E09` 等季号可联合验证。多季合集中有唯一且明确匹配的目标季目录时，订阅会指向该子目录；不会把其他季一起加入。目录中混入冲突季数、旧电影或仅有不完整片名时仍拒绝自动订阅。视频名中的月份标签、已知版本标签和独立的零补齐集数会被识别；不会猜测被替换的片名字词。具名视频与其父目录可分别提供可信别名和年份，缺少年份或存在冲突时仍拒绝。报错可展开“查看搜索详情”，了解已尝试关键词及来源故障；部分源不可用不会被表述成全网没有资源。

查询数量、页面大小和并发均有限制。时间预算用于停止后续查询，操作系统 DNS 解析和远端缓慢发送响应头仍可能延长实际等待时间。

自动查询复用搜索服务缓存，避免每次订阅强制重新抓取全部频道；每个候选分享仍实时验证。需要强制刷新索引时，可使用任务列表的手动搜索按钮。

开启“删除子目录后重存”的任务不会自动换源，以免新来源触发已有删除规则。单任务可在 JSON 配置中设置 `auto_repair: false` 禁用换源。

热门订阅运行时还会检查明确集号之间的缺口，例如 `01、03、04、05、05.mkv` 去重后缺第 2 集；从其他通过同作品、同季、已知年份验证的分享中仅补入缺号，再交给下载插件，保留原订阅继续追更。每轮只进行一次有界补搜，未补齐会打印剩余缺号并在下次运行重试。不会根据文件数量推断集数，也不猜测首集之前或最新集之后是否还缺集。

自动补集目前限单季、可可靠解析集号的热门任务；使用起始文件、重新编号、删除重存、混合季目录或无法识别文件名时跳过。最多检查 3 个空子目录；非空子目录需先确认季别，不自动跨目录补集。无法找到包含缺号的有效分享时会保留原状并说明原因，不表示资源已完整。关闭“分享失效时自动搜索并替换”也会关闭自动补集。

## 4. 热门追更

左侧“热门追更”按周一到周日显示，分国漫、动漫、电视剧，默认打开国漫。一键订阅先搜索并验证资源，再保存任务并立即调用转存，之后按系统定时规则持续追更。重复点击或来源切换时会检查已有订阅。若浏览器在创建订阅后关闭，已保存的任务仍会在下一次定时运行时执行。

一键搜索失败后，可在报错下方粘贴该作品的夸克分享链接（可包含提取码）。此方式直接验证所填分享，不依赖搜索引擎；仍需通过同作品、同季、已知年份及实际视频检查，成功后沿用原订阅目录、命名和 Aria2 设置。请粘贴夸克分享链接，而非 Google 搜索页或普通资源帖子。

- 国漫整合哔哩哔哩官方国创周历与 TVmaze 中国电视/网络播出排期，无论 Bangumi 是否可用均独立显示；TVmaze 国漫最多收录本周 60 部，实际数量以来源为准。同日同规范标题优先显示 B站官方条目，不合并明确不同季的标题。
- 国漫按来源分组、各自热度排序，B站追番人数不与 TVmaze 的 0–100 热度混算。B站条目显示集数及已发布、待发布或延期状态。
- 动漫使用 Bangumi 当季周播表，按“在看人数”排序，并排除首播日期仍在未来的条目。该表不保证反映临时停播、调档。
- 电视剧使用 TVmaze 中国播出日历，展示本周热度前 10 部，按实际集日期归日；不代表全网完整影视榜。
- Bangumi 不可达时，优先使用本周缓存；无缓存时提示来源错误，国漫栏目继续可用。
- 电视剧与 TVmaze 国漫保留普通季号，避免第四季误订到首季；来源的年份型季号不会被当成几千季。国内年番与来源季号不一致时，可能需要手动选取正确分享。来源未提供当前季年份或重拍版本时，请核对实际目录。
- TVmaze 官方链接指向同一哔哩哔哩节目时，会核对 B站媒体/季度 ID，在同日同系列的重复条目中优先保留 B站周历，避免将连续更新误显示为额外一季。身份核对失败时保留来源条目，不凭相似片名合并。
- 数据缓存一小时，错误后五分钟重试。刷新按钮重新读取当前缓存，不会强制高频抓取外部源。
- 新热门订阅每日按定时规则检查；周历展示首播安排，网盘资源上传时间可能更晚，所以不会只在播出当天检查。

数据来源：[Bangumi API](https://github.com/bangumi/api)、[TVmaze API](https://www.tvmaze.com/api)。TVmaze 数据按 [CC BY-SA](https://creativecommons.org/licenses/by-sa/4.0/) 使用，页面保留条目来源链接。两种来源热度口径不同，不混合比较。

国创官方日历：[哔哩哔哩国创时间表](https://www.bilibili.com/guochuang/timeline/)。各来源仍可能漏收录或错填日期，不保证涵盖每部周更国漫，也不会凭印象补写更新星期。首次打开需要汇总多个来源及中文别名，通常比缓存刷新慢。

## 5. 下载到 NAS 本地磁盘

本项目已有 Aria2 下载插件，安装或使用 NAS 上现有的 Aria2 服务后：

1. 系统配置 → 插件 → aria2，填写 `host_port`（如 `http://NAS局域网IP:6800`）、`secret` 和 `dir`。
2. `dir` 是 **Aria2 进程看到的下载根目录**，默认填写 `/downloads`。热门任务的 `save_path` 为 `cartoon`，所以文件直接下载到 `/downloads/cartoon`，不再追加剧名或来源子目录。NAS 上的实际位置由 Aria2 容器的目录挂载决定。
3. 开启“热门订阅通过 Aria2 下载到 NAS”并保存。仅填写 RPC 连接参数不会启用下载。
4. 保存后，新旧热门订阅都会启用下载；刚启用的旧任务会在下一次运行时补交符合条件的视频。默认不下载字幕，需要时将该任务 `addition.aria2.download_subtitles` 设为 `true`。到“任务列表”运行原任务即可，无需删除文件或重新订阅。
5. 日志出现 `Aria2已提交` 和 `GID` 表示下载器已受理；实际进度、完成情况和磁盘路径在 Aria2 查看。RPC 未连接、任务未开启、请求被拒绝会分别提示。

无法提交的文件及未扫描成功的子目录会保留到下次运行重试，即使没有新转存也会重试；不保存临时下载直链或 Cookie。普通手动任务仍使用自己的 `addition.aria2` 设置：开启 `auto_download`，需扫描旧子目录时开启 `download_subdir`，下载仍平铺到目标目录；要补交历史文件，可将 `download_existing` 设为 `true`，完成扫描后自动关闭。共享目录补交只选择能按当前任务标准命名规则确认归属的文件；不认领其他剧集或纯集号文件。重命名失败的文件保留待办，成功更名后才提交下载。显式再次补交会重新提交目录中的允许文件，适用于此前尚未下载的任务。

这里不内置第二套下载器；Aria2 负责下载队列、磁盘空间和重试。夸克 Cookie、账号权限和下载直链可用性会影响实际下载。系统中“通知测试”按钮包含上游的转存/清理测试；建议验收自己的独立测试目录。

## 6. 更新、备份与回退

V3.3 会迁移工厂默认设置：热门任务原 `/追更/片名` 改为 `/cartoon`，空白或旧默认命名改为 `片名 S01E01.原后缀`；全局旧默认 `/Downloads` 改为 `/downloads`。自定义目录和命名规则保留。实际迁移旧目录的任务会清除旧下载待办，已开启下载的任务重新检查新目录。更新只调整配置与后续任务，不移动或删除 NAS 上已有文件。

### 已安装并行发布包（`/root/quark-save-gpt`）

以下从旧维护版更新至 V3.4：先下载并检查新配置、拉取镜像，再停止维护版并备份；保留原 `.env`、Cookie、订阅和端口，不影响原作者版本。

```sh
(
set -e
cd /root/quark-save-gpt
curl -fL --retry 2 https://github.com/loren1997/quark-auto-save/releases/download/maintenance-v3.4/compose.yaml -o compose.yaml.next
docker compose -p qas-maintained -f compose.yaml.next config --quiet
docker compose -p qas-maintained -f compose.yaml.next pull
backup="backup-v3.4-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
docker compose -p qas-maintained stop quark-auto-save
cp -a compose.yaml .env config "$backup/"
mv compose.yaml.next compose.yaml
docker compose -p qas-maintained up -d
docker compose -p qas-maintained ps
)
```

更新后强制刷新浏览器页面。默认仍访问 `http://NAS局域网IP:5006`；如果 `.env` 改过 `QAS_PORT`，继续使用该端口。需要回退时停止维护版，将这次备份中的 `compose.yaml`、`.env` 和 `config/` 恢复到原位置后重新 `up -d`。

### 从源码构建的安装

更新前备份整个 `config/` 目录。在项目目录：

```sh
docker compose stop quark-auto-save
```

下载 ZIP 安装的用户可覆盖代码文件，再执行构建；保留 `.env` 和 `config/`。不要用上游 Watchtower 更新命令替换本维护版镜像。

回退时停止服务，检出上一个已验证提交或换回之前代码，再恢复对应配置备份、重新构建。备份里可能含 Cookie，妥善保管。

GitHub Actions 会先跑 Python 3.11/3.13 测试，再构建 amd64/arm64 镜像到该仓库的 GHCR。Fork 的 Actions 可能需要你先在 GitHub 的 Actions 页启用；仓库连接器还需要有该 Fork 的访问权限。镜像第一次发布后若为 private，需要在 Packages 中设为 public 或在 NAS 登录 GHCR；本地 `build` 安装不受此影响。只有 Actions 实际通过后才能确认远程镜像已发布。

## 7. 排错与验收

- 无法搜索：查看页面源错误和 `docker compose logs --tail=100 pansou`；确认地址为 `http://pansou:8888`。公共 `https://so.252035.xyz` 可作备用，但没有稳定性保证。
- 动漫源超时：页面会显示降级。如果你有自己的网络代理，可在 Compose 的服务 `environment` 中配置标准 `HTTPS_PROXY`，同时设置 `NO_PROXY: localhost,127.0.0.1,pansou`；不要关闭 TLS 校验。无需代理也能查看可达来源。
- “未找到匹配的有效资源”：展开“查看搜索详情”区分来源故障与候选验证失败；已有有效分享时，可在热门页报错下粘贴该作品的夸克链接直接验证订阅。日历有片名不保证分享存在或可用。
- 网页搜索会分别显示 Bing、DuckDuckGo 及落地页的 DNS、TLS、代理、验证码、超时等错误；只有真实代理故障才需要检查代理设置。NAS 能正常搜到候选而验证失败时，应核对实际文件名称和目录年份。
- “配置已被更新”：任务自动换源或另一页面写入了新配置。刷新后重新编辑，避免把新订阅或修复结果覆盖掉。
- 订阅已创建但没转存：查看手动运行日志、Cookie 是否有效、目标网盘空间；在任务列表运行该任务重试。
- NAS 没有本地文件：先看网盘是否已转存，再检查 Aria2 的连接、密钥、容器目录映射和该任务 `auto_download` 选项。

建议验收顺序：登录 → 名称搜索 → 自有分享的单任务转存 → 热门周历切换 → 一键订阅 → 日志/网盘验证 → 按需验证 Aria2 本地文件。自动换源与并发保存已经有可重复模拟测试；真实账号操作需在你自己的环境完成。
